Problem Statement, Target Users & Objectives

Operational Pain Points in Modern SOCs

  • Alert Fatigue: SOC analysts face hundreds of noisy anomaly alerts daily without context.
  • Black-Box ML Detectors: Classifiers flag anomalies without root cause attribution or MITRE mapping.
  • LLM Hallucinations: Commercial LLMs invent nonexistent CVEs and disruptive remediation steps.
  • Uncalibrated Confidence: Deep models output dangerous 99% confidence on novel zero-day inputs.

Target Users & Project Objectives

  • Target Users: Tier-1/Tier-2 SOC Analysts, Incident Responders, Threat Hunters.
  • Objective 1: Multi-Agent Collaboration: Coordinator, Retrieval, Reasoning, and Verification specialists.
  • Objective 2: Tri-Modal Hybrid Retrieval: Dense embeddings + BM25 + NetFlow matching via RRF (k=60).
  • Objective 3: Calibrated Probabilities: Platt scaling reducing ECE by 86.5% (0.0037 → 0.0005).
  • Objective 4: Strictly Defensive Posture: Mandatory Human-in-the-Loop authorization gate.

Selected Base Research Paper: MAIN-RAG (ACL 2025)

Paper Metadata & Official Citation

  • Title: MAIN-RAG: Multi-Agent Filtering Retrieval-Augmented Generation
  • Authors: Ching-Yuan Chang, Chia-Hsuan Lee, Ning-Hsuan Wang, and Yun-Nung Chen
  • Venue: Proceedings of the 63rd Annual Meeting of the Association for Computational Linguistics (ACL 2025), pp. 2607–2622.
  • Status: Peer-Reviewed Full Research Paper at Flagship NLP Conference.

Core Methodology & Contribution

  • Replaces single monolithic RAG with multi-agent filtering.
  • Decomposes pipeline into query planner, retriever, passage filter, and answer verifier.
  • Demonstrates that isolating passage filtering and verification substantially reduces context noise.

Key Limitations Identified in Base Paper

  • Evaluated only on open-domain QA (HotpotQA) - lacks cybersecurity domain adaptation.
  • Relies on verbalized LLM self-confidence without statistical calibration.
  • Text-only modality: cannot ingest structured network flow telemetry.
  • Unbounded feedback loops introduce latency unacceptable for SOC triage.

How MAIN-RAG Inspired ThreatRAG: Adoption, Adaptation & Extension

1. What We Adopted

  • Decoupled Roles: Separating the verification and filtering specialist from the generator.
  • Iterative Feedback Loop: Re-retrieving evidence when verification identifies missing support.
  • Stateful Orchestration: Shared typed workflow state (ThreatRAGState) across all agents.

2. What We Adapted

  • Domain Verification: Auditing against MITRE ATT&CK Matrix v14.1 and CISA KEV catalog.
  • Epistemic Separation: Strictly separating empirical telemetry facts from adversary hypotheses.
  • Citation Precision: Rigorous extraction of bracketed chunk IDs and Faithfulness scoring.

3. What We Extended

  • Tri-Modal RAG: Dense + BM25 + Structured event matching via Reciprocal Rank Fusion (k=60).
  • Platt Calibration: Post-hoc scaling on LightGBM reducing ECE by 86.5% on 6,000 flows.
  • Human Gate: Mandatory human sign-off for defensive containment actions.

ThreatRAG Multi-Agent Architecture & Communication Flow

4 Specialized Collaborative Agents

  • Coordinator / Planner: Decomposes query, formulates workflow plan, schedules specialists, manages state, and caps retries (max_retries=2).
  • Retrieval Specialist: Hybrid dense-sparse retrieval across 1,074 chunks + query expansion on feedback requests.
  • Reasoning Specialist: Calibrated LightGBM inference, ATT&CK mapping, fact/hypothesis separation, playbook synthesis.
  • Verification Specialist: Audits citations, checks faithfulness, detects insufficient evidence, triggers feedback loop.

Observable Trace & Feedback Loop

[User Query / NetFlow] → Coordinator Agent
  ↓ (Structured Execution Plan)
Retrieval Specialist ↔ [1,074 Chunks (ChromaDB + BM25)]
  ↓ (Top-k Hybrid Candidates)
Reasoning Specialist ↔ [Calibrated LightGBM Classifier]
  ↓ (Synthesized Analysis & Citations)
Verification Specialist — Insufficient? → [Feedback Loop]
  ↓ (Verified & Faithfulness Audited)
Human-in-the-Loop Gate → [Final Response]

  • CIC-IDS2017 Benchmark: 30,000 balanced flows (18k train, 6k calibration, 6k held-out test).
  • Indexed Corpus: 1,074 structured chunks with SHA-256 integrity manifests.

Models, Frameworks & Serving Stack

  • Dense Embeddings: all-MiniLM-L6-v2 (384 dimensions) in persistent ChromaDB.
  • Sparse Lexical Search: rank-bm25 (BM25Okapi) with cybersecurity entity tokenization.
  • Cross-Encoder Reranker: ms-marco-MiniLM-L-6-v2 for candidate rescoring.
  • ML Classifier & Calibration: LightGBM + Platt Scaling (ECE reduced to 0.0005).
  • Serving Stack: FastAPI backend (port 8000) + Streamlit dashboard (port 8501).

Qualitative Case Analysis, Failures & Quality-Cost Trade-Offs

Success Cases vs. Failure Case Analysis

  • Success 1 (TID-001): Port 80 SYN flood (85k pkts/s). Baseline gave generic advice; ThreatRAG correctly flagged DDoS with 99.98% Platt confidence and mapped T1498.001.
  • Success 2 (HIS-004): Port 80 flood vs Dyn DNS. Baseline gave flat summary; ThreatRAG contrasted transport layer (TCP/80) vs application DNS (UDP/53).
  • Failure Case (TID-014): 'Quantum tachyon modulation'. Baseline hallucinated theoretical attacks; ThreatRAG caught low similarity (< 0.15), triggered 1 feedback retry, and correctly abstained with an insufficient-evidence qualification.

Quality-Cost Trade-Offs & Honest Limitations

  • Quality vs Latency: Multi-agent deliberation adds 3.53 seconds of latency, which is acceptable for SOC triage where wrong decisions cause massive downtime.
  • Quality vs Cost: Multi-agent uses 1.5x more tokens but costs only $0.00063 per query.
  • Current Limitations: Evaluated on Friday DDoS and benign flows from CIC-IDS2017; expanding to advanced persistent threat (APT) multi-day campaigns is ongoing work.
  • Dependency: Hybrid retrieval quality depends on initial BM25 tokenization preserving CVE punctuation.
